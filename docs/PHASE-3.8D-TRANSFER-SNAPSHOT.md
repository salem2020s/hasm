# Proposed authorized ordinary transfer snapshot

Status: internal read-only adapter implemented as a provisional checkpoint in CostFlowSnapshotService; broader mandatory regression matrix remains incomplete. It has no API, DI registration, production caller, execution path or migrations. Existing ordinary-only snapshot behavior is unchanged. Independent source review and focused PostgreSQL evidence do not establish full-phase completion or activation approval.

## Consistent authorized closure

Open only the requested company's resolved database, after live StockBalanceView permission for the requested warehouse. Use one REPEATABLE READ, READ ONLY transaction throughout. Resolve an ordinary untracked stock item, common current FIFO/average method and company base currency as the existing snapshot does; refuse changed/unresolved method and all unsupported item/history types.

Load the COMPLETE historical operation-connected warehouse component for this item: transfers in both directions AND every position touched by a multiline ordinary operation. Shared operations remain indivisible. The metadata quarantine below can expand this further. This is a conservative superset of the minimal affected closure, not a promise to compute the minimal proposal-specific impact set. Check live cost-visibility permission for every discovered warehouse BEFORE reading its cost amounts, and authorize the entire component before loading valuation history. Discover only group/warehouse/reference identifiers internally; never return a partial graph, hidden warehouse identity, count or value. A denied scope returns generic forbidden. Recheck all discovered scopes before returning any result or diagnostic, including failure paths; concurrent revocation cannot rely on the older company snapshot or a fingerprint.

Discovery is a metadata quarantine step, not a validity-filtered join. For every encountered operation, take the UNION of all actual entry warehouse references and resolvable source/target identifiers from its referenced document and exact stock-posting document links. Include malformed/wrong-kind/item legs for authorization purposes; they cannot qualify an operation for replay. Do not require a valid paired transfer or authentic source before discovering its referenced endpoints. Authorize every resolvable endpoint before reporting pair/source/sequence diagnostics, including missing hidden counterparts. The authorization quarantine may be larger than the supported transfer component. No joins may silently erase malformed evidence.

Also quarantine resolvable warehouse references in layer position/declared-warehouse/source-layer identity metadata and consumption target-layer metadata before structural diagnostics. A malformed reference to a foreign hidden layer must not bypass authorization merely because no valid transfer leg reaches it. Discovery reads identifiers only, not quantities/amounts, and consumes the same global work budget. Foreign-layer hidden-scope and failure-path revocation cases are mandatory before implementation is accepted.

Use bounded iterative discovery with batched frontiers, loading each warehouse and operation's metadata once, using parameterized queries and existing indices. Limit warehouse count10,000, groups100,000, entry legs200,000 and total stored layers/consumptions400,000. Additionally count ALL processed discovery rows, including duplicates and malformed references, against one cumulative400,000-row budget; each query uses remaining-budget+1, and consumption is checked before collection growth. Cap total company-database commands at20,000 and all async work/permission checks under one linked30-second operation deadline; do not reset these budgets per warehouse or query. Deduplicate operation expansion without deleting its raw evidence. Timeout/cancellation aborts the whole calculation without a structural diagnostic or partial result. Resource-limit errors disclose no counts or warehouse identities; never fall back to a smaller closure. Test repeated shared groups and malformed duplicates, not only many retained unique groups.

## Complete baseline classification and ordering

- Load every entry of each included position from sequence1 through LastSeq; check exact contiguous ordinals and nondecreasing effective dates, position/item/warehouse consistency and operation date.
- Ordinary receipt/issue operations retain all correct-direction/kind child entries for this item, including repeated positions. Transfers have exactly one source-out and one destination-in entry, distinct warehouses, equal quantity/amount and one common operation/date. No client supplies a transfer cost.
- Preserve each receipt layer and each per-line issue rounding, numeric CostEntry.Id child order, injective entry simulation identity and actual parent link. Use the reviewed PHASE-3.8D-MULTILINE-CONTRACT.md ordinal-range/block model; never sum or reprice ordinary children. The pure model and test-only mapping do not prove a general database loader complete. Until this actual adapter binds every child/range, it must refuse rather than return partial or aggregated evidence. Existing ordinary-only snapshot behavior remains unchanged.
- Refuse reversal kind/links/marked-reversed operations; stock adjustment origins; any negative obligation history, including settled/reversed rows; mixed epochs/method changes; tracked items and unknown source types. These histories cannot be recast as ordinary events.
- A null source needs a null source ID. Stock-document sources must match the exact stock posting's CostOperationId and authentic document type, effective date and source/target warehouse roles. Do not accept a matching document ID or warehouse alone. Current direct engine fixtures with null source remain supported as in the ordinary snapshot.
- Build one indivisible ReplayOrderGroup per operation/item using complete per-position ordinal ranges and ordered child bindings. CalculateBlocks must validate and schedule the complete baseline before its shared arithmetic runs. A returning warehouse path is valid; an operation dependency cycle, missing child/leg or chronology inconsistency is not.
- Reconcile every recalculated entry amount and running quantity/value with the original stored ledger, then every position's final quantity/value/sequence. Do not accept matching final totals when intermediate entries disagree.

## Persisted FIFO identity and consumption reconciliation

Simulation IDs never replace actual layer IDs. In replay creation order, bind each simulated creation to exactly one persisted layer of its entry/position, in actual FIFO layer sequence. Check original quantity/amount, item/warehouse/entry links and component order. A receipt layer has no source. A mirrored layer must reference the ACTUAL layer already bound to its simulated parent. Check complete one-to-one counts, positive distinct layer sequences and original/remaining bounds; never infer lineage from equal prices.

For every outflow, map its replayed consumption IDs through those bindings and reconcile ALL persisted consumption rows: entry, actual layer, exact quantity/amount and non-restoring direction. Preserve FIFO order using original layer sequence; reject extra/missing/duplicate or foreign-position components. Average positions must have no FIFO layers or consumption rows. Finally reconcile every remaining layer with replay's open layers, including positive-quantity FREE layers and fully consumed zero remainders. Check complete persisted layer/consumption counts so orphaned rows cannot disappear through a join or filter.

Return immutable baseline evidence with the company/item/method/currency, component positions, operation/entry history, actual-to-simulation bindings and a deterministic fingerprint. Fingerprint covers this complete read-only evidence, NOT approval, execution authority or a complete future plan; source revision, account/period/legal policy and adjustment contents must be bound separately before approval/execution.

## Mandatory PostgreSQL regressions before integration

Both methods: chained and returning transfers, free stock, posted-document provenance, repeated identical fingerprints, no created position/layer/audit writes, exact entry/final reconciliation, consistent snapshot during concurrent writer, live revocation across the whole component, hidden downstream/upstream/shared-operation warehouse refusal and company isolation. FIFO: multiple carried layers, partial downstream issues, real source-layer binding, consumption order, free open layers, closed layers and precise changed-layer refusal. Also require valid multiline receipts/issues across same/distinct positions retaining ALL children, per-line costs and ranges; malformed child linkage/ranges refused without aggregation; missing/malformed hidden counterpart and document endpoint authorization BEFORE structural errors; revocation on failure paths, duplicate discovery-work accounting, global query/deadline bounds, malformed source/date/sequence/layer/consumption evidence, all unsupported histories, changed methods, empty positions, cancellation and deterministic small-limit overflow. Verify original rows/journals unchanged and all exceptions return no partial evidence. Registry counts only increase for added PostgreSQL cases; no skips or weaker assertions.

The public feature, proposal scheduling/comparison and all reversal/negative/conversion/approval/persistence/execution/UI contracts remain unfinished.

## 4. Integration risks across merged phases (ranked)

1. **Migration contiguity and pins.** The loader refuses gaps; company 0026 / system 0027 are now used by pricing. Any branch with its own migration (PR #48 ends at company 0021 / system 0023 and plans new numbers; the customer-group registry; backup coordination) must renumber from company 0027 / system 0028 when it merges. Pinned counts exist in at least 15 places (`Assert.Equal(26L ...)` in BranchTests, ChartTests, CompanyConfigurationTests, CompanyProvisioningTests, CompanyRuntimeIsolationTests, CompanyRuntimeTests, FiscalTests, WarehouseTests; 27 in SystemDatabaseTests); each new migration needs all of them raised in the same commit or CI fails late. Suggest a single constant (follow-up; do not change tests in an unrelated PR).
2. **PostgreSQL registry in `backend.yml`.** The exact per-class counts file is shared by the hosted and self-hosted jobs; two PRs that both add a class (e.g. pricing API 3 tests and a backup test) conflict textually and the total ("1022 -> 1025") silently diverges after a merge. After every merge, recompute the total and per-class map; never lower.
3. **Permission seeding.** Pricing permissions arrive through system migration 0027, and role presets must include them for the Administrator and any "accountant"/"viewer" preset; each new permission requires (a) catalog, (b) system migration seeding for existing companies, (c) preset, (d) a test that a company created BEFORE the migration receives it (upgrade path). Verify for 0027 and for any backup permission added by another agent.
4. **Attachment and key coordination for backup.** A backup set needs company DB + attachment folder + key directory from the same moment (`docs/PHASE-3.12.md`). Risks: key retired while retained attachments still need it (decision K); backup job touching the key directory without the `oldKeysMayBeRetired` report; removed attachments' bytes kept (decision R) so restore must not purge; restore of one company must not overwrite another company's folder (storage names are per company). A drill test on the isolated cluster is the missing proof (21.8).
5. **Customer groups unfinished.** Pricing has no group scope (tracked as an unfinished Release 1 requirement); a later forward migration changes entry/discount uniqueness and the snapshot version rules (`pricing-snapshot-v1` hashes are pinned by a golden-hash test and must not change).
6. **Quote request trust.** The quote endpoint accepts `itemGroupId` and `unitCost` from the client and verifies neither against the item; acceptable for a preview, but the document framework (3.13) must derive group and cost server-side before sealing.
7. **Single-pass CI gaps.** Frontend/Tauri: only a debug build and one smoke spec; the Web/Desktop parity rule is therefore enforced mostly by sharing code, not by tests. Rust `cargo audit` is absent (decision C).
8. **Blocked chain.** 3.8C/3.8D blocked on owner decisions; scenarios 21.5 and part of 21.4 cannot pass until resolved.

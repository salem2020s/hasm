## 2. Principles
Real posted data only (no estimates, no fabricated or approximated figures); historical figures never change when later master data changes; every report reconciles to the General Ledger and Trial Balance and states the check on screen; base currency presentation (original currency shown in the ledger as today); authorization before pagination, totals and export; deterministic ordering; Arabic and English; one shared React screen for Web and Tauri; Cost of Sales content that needs inventory, sales or purchasing data stays "not applicable" (never zero) until those phases.

## 4. Schema, permission and dependency changes needing approval
* **Permissions (system migration 0014):** statements view and export codes (decision 5.6).
* **Classification storage (company migration 0011), only if decision 5.1 chooses an explicit mapping:** a company-level statement-line mapping table (group or account → statement section), seeded for template charts.
* **No other schema change** is planned: statements are computed read-only from the posted journal; export audit uses the existing business audit with a new event type.
* **Libraries to vet before use (decisions 5.2, 5.3):** an .xlsx writer and a PDF engine; each must be license-compatible, maintained, free of known vulnerabilities and (PDF) able to shape Arabic.

## 5. Consequential decisions needed from the owner
1. **Statement classification.** The chart stores only type (Asset, Liability, Equity, Revenue, Expense), nature and group/postable; it has no "current vs non-current", "cost of sales vs operating" or "other income" attribute. Options: (a) derive sections from the chart hierarchy and the template group structure (works for template charts and conventional charts, fragile for charts built differently); (b) **recommended:** a small explicit company-level mapping of groups/accounts to statement sections, defaulted from the templates, with an "unclassified" line so nothing is ever dropped. (b) needs migration 0011.
2. **PDF engine.** Arabic needs real text shaping and embedded fonts. Candidates: a server-side library with HarfBuzz shaping (license to be checked, e.g. QuestPDF's community terms), or client-side print-to-PDF from the shared UI (no extra library, but no server-side deterministic file/audit). Recommendation: a short proof-of-concept inside S5 before committing; the owner decides on license acceptability.
3. **Excel writer.** Recommendation: an MIT-licensed OpenXML-based writer (for example DocumentFormat.OpenXml or ClosedXML), vetted like ExcelDataReader was; the existing read-only reader is used only to verify output in tests.
4. **Export limits.** Excel allows 1,048,576 rows per sheet; proposal: synchronous streamed export up to a documented limit (for example 500,000 rows) and a clear refusal above it; background export jobs only if the owner needs larger files.
5. **Comparatives.** Proposal: previous fiscal year and previous period of the same year (actuals only); budgets are out of scope.
6. **Permissions.** Reuse `company.ledgerreports.view/export` for TB and GL, and add `company.financialstatements.view/export` for the statements (branch-scoped like the ledger reports), or reuse the ledger codes for everything.
7. **Current-period result on the Balance Sheet.** Proposal: shown as its own computed line ("Result of the period not yet closed") that disappears into Retained earnings after the closing entries; not stored.
8. **Trading Account applicability.** Proposal: the statement appears only when accounts classified as cost of sales exist; otherwise it is reported "not applicable", never zero.
9. **Date range rule.** The current 5-year maximum range stays unless the owner prefers a different limit (comparatives span two ranges).
10. **PDF layout.** Page size (A4 only?), company logo/letterhead, signature lines; the visual identity rules in SRS §13 apply; the document designer remains a later phase.

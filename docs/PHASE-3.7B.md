# HASM — Phase 3.7B: Atomic inventory posting (as built)

Second slice of Phase 3.7. It turns an **approved** stock document into a real stock effect with its exact valuation and its accounting side, in one transaction. Source decisions: SRS 7.4, 9.3, 9.6, 9.7, 17.4, 19.2, 19.5, 19.7; ARCHITECTURE 5, 7, 8; roadmap resolution T-1 (physical execution and financial journal status are separate, explicit facts).

* **Company migration 0016** (`CompanySchema.StockPosting.cs`): `StockPosting` (one row per executed document, unique per document and per costing operation: document, type, effective date, recording time and poster, costing operation, accounting configuration version, journal entry, total value), `StockPostingLine` (per line: item, warehouse, base quantity, exact value — this keeps the receipt amounts the poster entered) and `StockPostingEvent` (append-only accounting-state history: 1 = journal draft pending approval and posting, 2 = no journal required). All three are **append-only** (PostgreSQL refuses update, delete and truncate); the runtime role has SELECT and INSERT only. A trigger on the document table refuses to cancel an executed document even for a direct statement.
* **System migration 0018:** permission `company.stockdocs.post` (warehouse-scoped, Company Administrator preset).
* **Execution = existence of a posting row.** The document's own status stays *approved*; nothing in the document tables changes. The word *posted* belongs to the journal and the accounting state only (T-1).
* **One transaction** (`StockPostingService`, after the warehouse-structure advisory lock and the document row lock): revalidate the document (items active, stockable and untracked, units, active warehouses and branch, stored base quantities still equal the recomputed ones, **open** fiscal period), check the live inventory and counter accounts, cost the movement through `InventoryCostingService` with key `stock_document:<id>` (receipts use the exact per-line amounts entered by the poster; issues and transfers are costed by the engine at actual cost; equal items of a transfer are summed first), create one **balanced draft journal entry** through the automatic journal path with the same key (receipt: debit each item group's inventory account, credit the receipt counter account; issue: debit the issue counter account, credit the inventory accounts), insert the posting, its lines and the first accounting event, append the audit event 1161. Any failure rolls back the stock, the cost operation, the journal entry and the posting together: there is never a stock effect without its valuation and accounting state, and never a quantity-only posting.
* **No journal when none is due:** a zero-value receipt, and a transfer (it nets to zero inside the same inventory accounts), need no accounting configuration and create no entry; a receipt or issue with value is refused with `inventory_accounting_not_configured` (or a specific account refusal) before or after costing, and the rollback leaves nothing behind.
* **Idempotent and concurrency-safe:** a repeated request returns the original posting (`replayed = true`) without writing anything; different receipt amounts for an executed document are refused (`already_posted`); simultaneous requests produce exactly one stock effect and one journal entry. `If-Match` carries the document revision (428 missing, 412 stale).
* **Authorization:** `company.stockdocs.post` on **every** warehouse the document involves, plus the right to see it; a document the caller cannot see is never revealed.
* **API:** `GET|POST /api/v1/company/stock-documents/{id}/posting`; the capabilities response gains `post` (the warehouses where the caller may post).
* **Tests:** PostgreSQL `StockPostingTests` (11) and `StockPostingApiTests` (1): receipt/issue/transfer with exact figures, the draft journal, atomic rollback after costing, insufficient stock, missing configuration, validation of amounts, non-approved/stale/closed-period refusals, idempotent retry and four simultaneous requests, cancellation refused after execution (service and database), warehouse-scoped authorization, append-only records, HTTP flow. CI expected PostgreSQL count 881.
* **Not in this slice (3.7C, 3.7D):** reversal of an executed document, resolution of the accounting-pending state when the journal is approved, posted or rejected, the period-close probe for pending states, the shared UI. The receipt cost is entered by the poster per line, exactly, and may already include allocated freight, duties or discounts; nothing is excluded: purchase-cost adjustments (freight-in, duties, rebates, discounts) are designed as explicit audited adjustments in Phase 3.15 under open decision OD-2, which only needs the owner to confirm the accounting treatment, and revaluation arrives with Phase 3.8D.

# Phase 3.8D prospective-conversion transition contract

Status: **implementation design proposal for independent review; execution is NOT implemented or enabled**. Owner-approved accounting bases are D-044 and D-045 in [DECISIONS.md](DECISIONS.md), approved 2026-11-17. This document proposes deterministic consequences of those bases and identifies required proofs. It does not approve a new jurisdictional rule or relax existing database guards.

## 1. Basis and ordering

Each conversion has an immutable source document/revision, explicit effective date, old/new methods, company/item/warehouse scope, predecessor-basis identity, exact carrying quantity/value and complete plan/approval references. Conversion itself changes neither quantity nor carrying value. A distinct requested revaluation is not folded into conversion; it has its own approved compensation. FIFO to average uses the exact remaining total. Average to FIFO creates one auditable opening conversion layer, preserving the exact total and linking to its predecessor basis. Zero quantity requires zero value.

The persisted basis needs a forward-only reviewed migration: existing cost operations, entries, original layer quantities/values and journals are never rewritten. Existing CostPosition.Method immutability is a real database barrier, not an application flag to disable. Before persistence design is accepted, specify how append-only basis epochs, the current position and reconciliation agree without double-counting retired FIFO layers. No new operation-kind value is assumed to fit existing constraints. A new prospective conversion follows the affected positions' terminal committed movements at its permitted effective date; it does not replace an earlier historical method. Back-dated ordinary documents may still require replay through an already recorded conversion boundary as described below.

For a reproducible impact plan, preserve each existing position's event sequence, group transfer legs as one event, retain original/reversal dependencies and include conversions as explicit basis boundaries. A proposed event follows existing events of its effective date. Cross-position scheduling must use a deterministic dependency graph; a cycle or unresolved origin refuses the whole plan, never drops a leg. A revised event before an existing conversion must replay through that boundary and all downstream transfers. The hypothetical conversion preserves the revised quantity/value at that boundary; the stored original conversion evidence remains immutable, with differences represented by the new traceable plan and compensations.

The snapshot fingerprint must bind every affected basis, position sequence, source revision, original/reversal/transfer link, obligation/settlement state, period state, proposed contents and relevant mapping versions. The current internal ordinary-history fingerprint is insufficient and must never be reused as an executable token. Authorization/revocation is checked live independently of the fingerprint.

## 2. Reversing an outflow from an earlier basis

The reversal restores the original quantity and exact recorded cost; it does not price a return at today's average or selling price. Its accounting reversal/compensation uses the original accounts and dimensions where valid and legally permitted (D-044). If an earlier back-dated adjustment changed the relevant approved economic cost, the plan must explicitly reconcile the original and all linked compensations, not reverse only one leg or count them twice.

When the current basis is average, add the restored exact quantity/value to that basis. When the current basis is FIFO, create a new restoration layer at the reversal event's place in the current epoch, linked to the original consumption provenance. Do not reactivate archived pre-conversion layers as if they were current layers. Preserve deterministic original-consumption order when several restoration components exist. The original consumed-layer record and original posted operation remain unchanged.

Example: an average outflow consumes 2 units worth 30; the remaining position 8/value120 is converted to one FIFO opening layer. Reversing that outflow later restores 2/value30 as a linked current-epoch restoration component. Total becomes10/value150; the opening conversion layer's original 8/value120 is not rewritten. Conversely, an old FIFO outflow of2/value20 restored into an average position8/value120 gives10/value140, not10/value150 by repricing the returned goods at the current average.

Cross-epoch FIFO ordering example: initial FIFO layers A2/value20 then B4/value80; an issue of3 consumes A2/value20 and B1/value20, total40, leaving3/value60. Convert to average, receive1/value40, then convert back to FIFO. The current opening layer F is4/value100. Reversing the earlier issue now appends restoration components R-A2/value20 then R-B1/value20 **after F**, in the original consumption sequence. Current total is7/value140. The next issue of5 consumes F4/value100 and R-A1/value10, amount110, leaving R-A1/value10 and R-B1/value20 (2/value30). Archived A/B balances are historical evidence only and are never included in the current-layer sum or restored a second time. The live layer order is a current-epoch event ordinal plus component ordinal, never a UUID or an archived arrival rank.

## 3. Reversing an inflow from an earlier basis

The executable direct-path rule is deliberately exact: **if the inflow's basis identity differs from the current basis, direct reversal returns `impact_recalculation_required` for every old/new method combination** (FIFO-to-average, average-to-FIFO and FIFO/average returning to the same method through an intermediate epoch). A merged opening layer or sufficient total quantity never proves an earlier receipt untouched. Cross-basis inflows use the complete guarded impact/reconciliation path; this is not a permanent exclusion of their correction from Phase 3.8D.

Within one unchanged basis, keep the existing engine's direct-reversal proofs: FIFO requires the original receipt layers fully remaining with exact original quantity/value; moving average uses the existing unreversed-later-movement proof (later originals already completely reversed do not falsely block it). Linked transfers obey the stricter rule of either leg. Do not introduce a shortcut for mixed average history. Negative-obligation history requires the complete obligation-aware path, even if the normal ledger entries alone appear reversible.

When direct reversal cannot be proved, return an explicit recalculation-required outcome and construct the complete reviewed impact plan, including all affected later issues, conversions, transfers and their separate compensation requirements. Do not silently issue at current FIFO/average cost, leave a negative layer, or remove only the quantity. The ordinary direct-reversal path stays refused until the guarded recalculation path can prove and atomically execute the complete correction.

## 4. Transfers across conversion boundaries

A transfer carries one exact amount out of its source and into its destination, each using its applicable basis. Conversion of either warehouse never changes the stored original transfer amount. A reversal removes/restores the linked pair atomically at that exact amount; the destination must satisfy the inflow proof above. If downstream consumption prevents it, plan the complete downstream recalculation instead of independently reversing either leg.

Example: source A transfers3/value45 to B; B later converts its average balance to FIFO. A reversal cannot merely credit B's current average or consume an unrelated FIFO layer for a different amount. It must remove the linked3/value45 with a proven reconciled trajectory (possibly through a complete impact plan) and restore3/value45 to A's current basis. Transfer-only movement creates no company-wide value gain/loss. Warehouse permissions and all affected periods are checked for both legs and the full downstream closure.

## 5. Linked returns and negative-stock history

Commercial return workflows belong to later roadmap phases, but their costing contract must reference the original document line, quantities, actual approved cost and any linked compensations. Cumulative partial returns/reversals must not exceed the remaining returnable quantity/value. Use existing fixed-unit arithmetic and exact final remainder conservation; do not recompute historical cost from a rounded displayed unit price. Refund/pricing/tax rules are separate and are not introduced here.

Proposed deterministic allocation contract: the approved current economic-cost entitlement of a source line is its original exact cost plus every linked approved compensation round, with an immutable revision and ordered provenance components. FIFO components follow the approved issue's replay-consumption sequence; average has one aggregate component. A partial return consumes the earliest remaining component quantity first, using `CostingMath.Proportion(remaining component value, returned part, remaining component quantity)`; taking the whole component uses its exact remainder. The remaining entitlement excludes all earlier returns and their linked compensations. The plan binds this entitlement revision and all allocations; cumulative quantities and exact values are capped at the entitlement. A whole-operation reversal must likewise exclude quantities already returned, or require complete reconciliation; it cannot restore them twice.

If a new compensation round changes an already partially returned source, the complete plan must also reconcile those prior returns through separately approved linked compensations before using a revised remaining entitlement. Refuse a missing, stale, negative or unreconciled entitlement; do not silently reprice a prior return or subtract its unadjusted original amount from a newly revised total. Each accounting component retains its original valid account/dimension lineage; netting values must not erase classification. These allocation/provenance records and their constraints still require persistence design and tests.

Exact-rounding example for one3-unit component: original total100 and an already returned1/unit cost33.33. A first approved compensation round changes total cost to101.01; the complete plan includes +0.34 compensation to that prior return, making its economic cost33.67 and the remaining2-unit value67.34. A second round changes the source total to100.99 and includes -0.01 compensation to that return; its economic cost becomes33.66, leaving2/value67.33. Returning1 more costs33.67 (half-away rounding of67.33/2); the final1 costs the exact33.66. Returned totals33.66+33.67+33.66=100.99. Original journals are unchanged; the source and prior-return compensations are separately linked, approved and counted once. Multiple FIFO components use the same rule per component in their recorded order, not a newly rounded average across unrelated components.

Never move an open negative-stock obligation into an ineligible FIFO basis. A conversion plan must account for every open, settled and reversed obligation and settlement, preserving D-019 eligibility and D-044 classification. A basis conversion is not a receipt and must not secretly settle or reopen an obligation. Settled history cannot be ignored just because the current open quantity is zero. The full negative-history transition matrix is a separate prerequisite to execution; this design does not supply it.

## 6. Approval, validity and execution barriers

All proposed source/adjustment contents remain non-postable proposal data until approved guarded execution materializes the complete execution group atomically. Validate current permissions, separation of duties, company/warehouse scopes, periods, immutable plan contents and original/reversal links under the normal posting locks. A source, basis, mapping, history or period change invalidates the whole group and its approvals. Idempotent retries cannot materialize a second group. Any failure rolls back source, basis, stock, accounting, linkage and audit effects together.

Final Closed periods remain barriers across the affected plan; neither a current-dated compensation nor a conversion permits silently rewriting a closed period. Pending accounting remains explicit and continues to block close where required. Missing, inactive or legally prohibited historical mappings require an explicitly approved valid remapping or refusal. Company/jurisdiction-specific restrictions must be configured or validated as an explicit release prerequisite; no generic compliance claim is made by this contract.

## 7. Mandatory regression matrix before activation

- Both conversion directions at zero and nonzero stock; exact quantity/value conservation; free stock and final-unit rounding; no historical record mutation.
- Pre-conversion outflow reversed after conversion under each new method, including multiple original FIFO consumptions and later movements; expected quantities, exact values, restoration order and immutable provenance.
- Pre-conversion receipt reversal with proven untouched stock, mixed/consumed stock requiring complete replay, and refusal when a complete plan cannot be built.
- Transfers where source, destination or both convert; both directions; chained and returning transfers; destination downstream consumption; pairwise and company-wide value conservation.
- Linked partial-return/reversal allocation with exact final remainder and cumulative caps; original and compensation references counted once.
- Open, partially settled, fully settled and reversed negative-stock history; ineligible FIFO conversion refused; no phantom receipt or reopened obligation.
- Proposed event before/same date/after conversion; deterministic full-closure scheduling and repeated identical output; unsupported/cyclic history refuses in full.
- Live revocation, hidden downstream warehouses, cross-company isolation, stale source/basis/mapping/period, approval invalidation, Final Closed periods, pending accounting and explicit jurisdiction-policy refusal.
- Concurrent conversion versus issue/reversal/transfer/recalculation; idempotent retry; injected failure at each persistence stage; complete rollback and audit integrity; fresh/upgrade migration and runtime-role grants.

These tests are **required, not yet implemented or passed**. Independent approval of this contract and all applicable implementation/tests are mandatory before any conversion execution path is activated. PR #48 remains Draft until its entire approved scope and exact-head gates pass.

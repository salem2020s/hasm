# HASM — Phase 3.7A: Inventory accounting configuration (as built)

First slice of Phase 3.7 (atomic inventory posting; see `docs/AUTONOMOUS-PROGRESS.md` for the dependency analysis). It builds ONE prerequisite of posting and **posts nothing**: no journal, no quantity, no cost.

* **Company migration 0015** (`CompanySchema.InventoryAccounting.cs`): `InventoryAccountingVersion` (default inventory account, receipt counter account, issue counter account, group count, content hash) and `InventoryAccountingGroup` (version, item group, inventory account). **Immutable and append-only** (PostgreSQL refuses update, delete and truncate); foreign keys keep every account and group real; nothing is hard-coded or seeded, so an unconfigured company cannot post.
* **Versioning:** every save is a new version holding the complete mapping; an unchanged configuration creates nothing and audits nothing; concurrency by version number (`If-Match`; 0 while nothing is configured; 412 stale, 428 missing); saves are serialised by an advisory lock; audit event 1160. A later posting records the version it used, so history is never reinterpreted.
* **Validation against the live chart at save time:** inventory accounts (default and per group) must be active, postable (not a group) **asset** accounts; counter accounts active and postable and never one of the inventory accounts of the same version; no account may be limited to a foreign currency (stock is valued in the base currency); groups must exist; no duplicates. The posting slice validates again at posting time.
* **Resolution:** `InventoryAccountResolver` / `InventoryAccountingService.ResolveAsync(work, groupId)`: the group's own account, else the nearest parent's, else the company default; refuses (`inventory_account_not_configured` / `inventory_accounting_not_configured`) when nothing resolves. Receipt/issue counter accounts are returned with the version for the posting slice to check per document kind.
* **System migration 0017**, permissions `company.inventoryaccounting.view|configure` (company-wide; Company Administrator preset).
* **API** `/api/v1/company/inventory/accounting` (GET with lookups of accounts and groups, GET versions, PUT); **shared UI** Inventory → *Inventory accounts*: tabs *Main accounts*, *Group accounts*, *Versions*; actions outside the tabs; read-only for viewers; Arabic/English, RTL/LTR; same on Web and Tauri.
* **Tests:** PostgreSQL `InventoryAccountingTests` (7) and `InventoryAccountingApiTests` (1): defaults and permissions, version immutability and concurrency (two simultaneous saves, one winner), unchanged saves, every validation rule incl. foreign-currency accounts, group-chain resolution, viewer vs configurer, HTTP flow with ETags; web `inventoryAccounting.test.tsx` (6). CI expected PostgreSQL count 869.
* **Next (3.7B):** the posting itself (state, authorized post action and permission, receipt cost input, costing, balanced draft journal with the explicit accounting-pending state, reversal, period-close protection).

**Review decisions recorded (independent review of PR #31):** the account lookup lists every active postable account to anyone holding the view permission (the screen cannot work otherwise; account codes and names are not secret within a company, and it is documented here as a data-exposure decision); a user who may configure may also read; a new note on an otherwise identical mapping is recorded as a new version, an identical mapping without a note changes nothing; inactive item groups are not rejected (the SRS is silent; revisit in 3.7B if posting needs it).

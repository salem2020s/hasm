* **Findings:** 0 Critical, 0 High, 1 Medium, 2 Low.
  * **M1 (Medium): "verified" certifies a primary altered after its run.**
    * The copier compares each file with the primary's CURRENT bytes. Ciphertext changed at the primary after signing (bit rot, tampering) is therefore copied to every destination and recorded as 2040 "verified" (reproduced above).
    * D-185 step 4 aims to catch this by checking the signed digests, and the owner's D-230 builds "fully successful" on a "verified copy". The window grows with catch-up replication of older runs.
    * The deviation is recorded only in PHASE-4.3.md "as built"; the D-185 row in DECISIONS.md still promises the signed-digest check.
    * D-185 is the lead's, so changing it is the lead's decision, not an owner question. Because the owner's D-230 relies on the meaning of "verified", the change should still be placed in the owner register as an information item.
    * Resolution, either:
      * (a) preferred: record a keyless, signed CIPHERTEXT inventory at run time (size and SHA-256 of every encrypted file, in the signed cleartext status or a separate signed document), and verify both the primary and the copy against it. This restores the intent of step 4 without the key.
      * (b) at minimum: amend D-185 in DECISIONS.md with the keyless definition and its limit, add the owner-register information item for D-230, and state the propagation limit in DEVELOPMENT.md. (a) then becomes a tracked follow-up.
  * **L1 (Low):** the copy creates subfolders inside staging (the system and company sets) but `fsync`s only the staging root and, after the rename, the destination root. After a power loss the entries of files in those subfolders can be missing from a published copy. This is fail-safe, because the next status sees an unclean, incomplete copy (exit 1), but the subfolders should be flushed too.
  * **L2 (Low):** the destination safety checks (links, overlaps) run once at the start of the command. `backup-run` copies after the whole run without checking again, so someone with write access to a destination's parent could swap in a link in between. This is the operator's domain, but the link check should be repeated on the destination path just before staging.

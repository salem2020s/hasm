  * **Medium V1 (4B's verification rule is not well defined, and its whole-stream mode is unworkable).**
    * (a) **Anchoring.** In the whole-stream mode, every fact newer than the last manual checkpoint (a fresh 2011, the latest 2040 or 2042) sits in the unanchored tail. The verdict is then `Incomplete`, which 4B itself says fails closed ("an incomplete verification (a missing checkpoint) FAILS CLOSED"). After activation, deletion would therefore be refused unless someone anchors immediately before every apply, and the plan says nothing about it.
    * (b) **Permanent block.** One record inserted by the runtime role with an invalid MAC makes the whole-stream verdict `Failed`. The table refuses removal even for its owner, so that row can never be removed: every later deletion fails closed forever, with no operator path. This is a permanent deletion denial of service with the runtime credentials alone. Fail-closed is the right direction, but it must be explicit and recoverable.
    * (c) **The per-event mode is undefined.** "MAC and chain link verified individually" is ambiguous, because after a forged record the next genuine record links to the FORGED record's hash.
    * Resolution: make the decision rule per record, and define it.
      * A fact is used if and only if `AuditVerifier.CheckRecord` returns `Ok` for it (hash and MAC under a known key) and its sequence lies in the contiguous range read in ONE read-only snapshot up to the stream head.
      * An invalid record is IGNORED as evidence and alerted (2048). It does not taint the genuine records before or after it.
      * Absence-based facts (no later 2040, no 2016, the unaccounted set, the last word) are evaluated over that contiguous range. This is sound against the runtime role, which cannot update or delete audit rows; a sequence gap, which only the owner could cause, fails closed (`audit_unverified`).
      * Keep the whole-stream verdict and the checkpoints as additional, alerting evidence: anchoring protects against the owner truncating the tail, which is outside the runtime-credential model. Alternatively, require apply to anchor the head itself through the existing anchor path before it reads.
      * Add tests: a forged row does not block later genuine facts but is alerted; a fact in the unanchored tail is usable under the per-record rule; a sequence gap fails closed.

## Binding requirement for the implementation of 3.14 S2 (L-a, recorded; no plan text changed)

The database guard on voucher-owned journal entries MUST recognise the legitimate voucher-level void: cancelling a voucher-owned entry is allowed only when its owning voucher or transfer is set voided or reversed IN THE SAME TRANSACTION. A direct journal-level `ReverseAsync` of a POSTED voucher-owned entry MUST be refused the same way (the only reversal path is the voucher-level `reverse` action). Both behaviours get tests in `CashVoucherEntryUniquenessTests`: (1) the voucher-level void cancels the draft entry and voids the voucher in one transaction, and a direct cancel of the same entry is refused; (2) a direct journal-level reversal of a posted voucher-owned entry is refused with a stable code, while the voucher-level reverse action succeeds and links the reversal chain. The guard must not block the period-close probes or reversals of non-voucher entries.

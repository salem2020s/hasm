  * L3 (Low, new): the clocks differ. The guard compares the expiry with the DATABASE clock, while TryBeginAttemptAsync compares it with the APPLICATION clock. If the application clock lags the database clock by Δ, a challenge in the last Δ of its life is deletable (the database considers it expired) while the store still honours it. A delete and re-insert in that window resets the budget and the single use; the first probe pass shows it with a large Δ. With NTP, Δ is well under a second, so this is a narrow residual. Recommended: give the guard a margin well below the purge's one day, e.g. refuse deletion while `OLD.expires >= clock_timestamp() - interval '1 hour'`, or compare the expiry with the database clock in TryBeginAttemptAsync. Either removes it without affecting the purge.

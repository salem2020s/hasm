  * **M1 (Medium), `src/backend/Hasm.Infrastructure/Backup/ReplicationPending.cs` lines 27 and 28 (the new guard), reached from `DeletionReadiness.Locations` line 49 and `RetentionService.PlanLocationAsync` line 255. Open.** A primary root that is a file-system root now makes two commands fail that worked before. `BackupSet.RealPath` returns the root WITHOUT its separator: the empty string for `/`, and by its code `E:` for `E:\` on Windows (`Path.GetPathRoot(full).TrimEnd(separator)`, no further part), which `Path.IsPathFullyQualified` rejects on Windows. Both callers hand that value to `Evaluate`, and the guard throws `ArgumentException`. `Hasm.Admin` accepts such a root (`Path.IsPathFullyQualified(args[1])` is true for `/` and for `E:\`). Consequence: `backup-status <root>`, the credential-free monitoring command of D-071, calls `DeletionReadiness.Locations` outside every `try` (Program.cs 201 and 213, also with no destination configured, the default), so it ends with an unhandled exception and a stack trace instead of its status and its exit code; `backup-retention-plan` reaches the same guard and none of its catch clauses (`BackupException`, audit exceptions, `IOException`) takes an `ArgumentException`. Reproduced on Linux for `/` at the library call (above): result before, exception now. A backup root that is the root of a dedicated volume (`E:\`) is an ordinary Windows setup; that case is derived from the code, not executed (no Windows here). Nothing is deleted and nothing is read as "independent", so the direction is the safe one, but it is a regression of an operational command that the PR states it does not have ("no behaviour change other than the guard") and no test covers a root primary. Suggested correction: keep the guard, and give it a root it can accept: the two callers pass a fully qualified form of the resolved root (a volume root keeps its separator; `Path.Combine(root, runId)` is then also no longer drive-relative on Windows), or a volume root is refused as a primary root where the argument is validated, with a stable code and exit instead of an exception; plus one test with a root primary through `DeletionReadiness.Locations`.

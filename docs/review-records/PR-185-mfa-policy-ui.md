## What was checked and holds

* **No loop, no sign-out.** `requireEnrolment` only sets the phase (never from `anonymous` or `mfa`), is idempotent and retries nothing; `handleError` tests the enrolment code before the 401 branch; the api client neither retries nor calls `onUnauthenticated` for it. The prompt calls only `/auth/status`, the two enrolment endpoints, `DELETE /session/company`, `GET /companies` and logout. On the server those are outside the company policy requirement (the `open` group uses the authenticated-only policy; the auth routes carry no company requirement), so the prompt cannot be refused by the thing it is resolving. After the enrolment the company is selected once; a second refusal ends in company selection (the hook sets the prompt phase first, the fallback then sets company selection; choosing the company again shows the prompt with the explanation and the two ways out).
* **A spoofed 403 cannot skip anything.** The code only ever makes the client MORE restrictive (the shell is replaced by the prompt). Nothing is granted client-side: the enrolment, the new session, the selection and the grants all come from server answers, and the grants are reloaded by `enterCompany` after the re-selection. Anonymous calls ignore the code.
* **State after the enrolment.** `adoptEnrolledSession` re-selects `pendingCompany` or the current company and replaces every grant set through `enterCompany`; on any failure other than 401 it clears company id and all grant sets before company selection; 401 ends the session. While the prompt is shown after a mid-session refusal the old grants remain in memory but no company screen is rendered, and every exit path replaces or clears them.
* **Gating.** Menu entry and route need `access.mfapolicy.view` (pinned by a test that the policy is never requested without it); without `access.mfapolicy.update` both fieldsets are disabled, there is no Save button and the submit handler returns. `roles` and `all` go through the confirmation dialog; `off` saves directly; the inline warning is shown for both.
* **No secret persistence.** The new files use no browser storage and no logging; the prompt reuses `VoluntaryEnrolment` unchanged (only exported).
* **No backend change.** The commit touches `docs/` and `src/frontend/` only.

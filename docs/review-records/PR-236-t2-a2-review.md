  * M1 (Medium), 0038 `f_6f7af27d`, the key rule; test bed `NewBed` (D1, D-248; design 4.1 and 4.3). A key registered with signer NULL is accepted, and the grant's signer id is then whatever the signed message claims. D1 requires the signed authorization of "a separately registered signer using a key", and forbids a silent downgrade to the in-application signer model. Design 4.1 allows a NULL signer only for resolution (ii)'s installation key, which is not approved or built (no approval signature, no per-signature TOTP). Under resolution (i), the independence rules of D2 and test 7 therefore test only a self-asserted id when the key is unbound: whoever holds an unbound key can sign as any "independent" person. The probe proves it, and the PR's own positive path does the same: every accepted grant in ReplayGrantVerificationTests uses an unbound key, and no test accepts a grant whose key is bound to its signer. Not exploitable with the runtime credentials alone (only the owner registers keys), hence Medium. Required change:
    * refuse a grant whose key has no signer (its own reason, e.g. `grant_key_has_no_signer`) until resolution (ii) is approved and built;
    * move the test bed to keys bound to the grant's signer, and assert the positive case;
    * keep the mismatch case (`grant_signer_is_not_the_key_owner`).

* **Findings:** no Critical, no High, no Medium; five Low (L1 to L5 below), none fixed in this head, none weakening an existing safeguard.
  * **L1 (Low), `run-oneshot.sh` lines 196-218 and 236-244, signal races in cleanup.** (a) `cleanup` sets `CLEANED=yes` before `trap '' INT TERM HUP`; a signal delivered between those two commands runs `on_signal`, whose `cleanup` call returns at once, and the script exits 130 or 143 with the cluster still running. (b) The worker subshell does not carry `HASM_TEST_ROOT` in the environment it was started with; in the instant between the end of `new-test-cluster.sh` and the `exec` of `run-pg-tests.sh`, `stop_run` finds no process, and `wait` then blocks, signals ignored, until the test run ends by itself. Both windows are a few instructions wide; in (a) the owner record stays and the next run or `--recover` cleans up, in (b) the teardown still happens, late. Suggested: ignore the signals before setting `CLEANED`, and signal `${INNER}` as well as the processes found by environment.
  * **L2 (Low), `run-oneshot.sh` lines 64, 128 and 138, also `run-isolated.sh` (unchanged, already on main).** The owner record is accepted with the glob `hasm-pg1-??????`, and `?` matches `/` in `[[ == ]]` (verified: `/tmp/hasm-pg1-/../xy` matches). The record lives in a directory checked to be owner-only, mode 700, so only the same user can write it, and `rm -rf` still requires a plain, owned directory without a `cluster` entry; accepted as hardening. Suggested: require the base name to match `^hasm-pg1-[A-Za-z0-9]{6}$` and the parent to equal the temporary base, in both runners.
  * **L3 (Low), `run-oneshot.sh` line 224, same pattern as `run-isolated.sh` line 255 on main.** `install -d -m 700 "${HASM_ONESHOT_RESULTS}"` changes the mode of an EXISTING directory (verified: a 755 directory becomes 700). A user who names a shared directory, for example `/tmp`, as root would close it to every other account. Suggested: create only what is missing and apply the mode only to the per-run sub-directory, in both runners.
  * **L4 (Low), `run-oneshot.sh` lines 75-80, 168 and 191.** When `/proc/self/net/tcp` cannot be read, or `awk` fails, `port_5433_listening` returns "unknown" and the script continues. This layer is then fail-open; the refusal is still made by the unchanged `new-test-cluster.sh` (`port_listening`, before anything is created) and by the server's own bind. Suggested: treat "unknown" as a refusal, or say in the comment that the creation script is the authority.
  * **L5 (Low, documentation of a limit), `common.sh` scrub.** As the diff states, only names that are shell identifiers are removed, so an inherited `Hasm:Section:Key` (which the .NET configuration also reads) survives, and `ConnectionStrings__*`, `DOTNET_*` and `ASPNETCORE_*` are not in the list.

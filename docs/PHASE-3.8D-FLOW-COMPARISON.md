# Internal ordinary component comparison contract

Implementation plan for the approved Phase3.8D ordinary-history path, not a new accounting decision or execution authorization. Full phase scope remains unchanged.

Load every proposed endpoint's historical closure in ONE authorized repeatable-read/read-only snapshot, including empty destinations. Never combine separate snapshots. Baseline evidence remains company/item/common-method/currency bound; unsupported reversals, negative obligations, adjustments, conversion epochs and tracked histories remain explicit refusals until their separate full contracts are implemented.

An ordinary proposal is one item/operation/date with1..500 receipt/issue children, or one transfer child with distinct source/destination. Each child retains its own quantity, receipt amount and rounding; no aggregation. Non-transfer destinations, issue prices, transfer prices, missing endpoints and invalid numeric values are refused. Endpoints must already be in the authorized read set; the pure comparison cannot expand authorization. Versioned deterministic synthetic child identities derive from the proposal ID/line index; they never replace real entries/layers, and collisions fail closed.

Extend the existing validated block replay with an insertion entry point. Preserve existing historical ordinal ranges and original child order/IDs. Proposal ordinals are local1-based ranges within its own operation; the existing ReplaySchedule.CalculateInsertion places the WHOLE proposal after all same-date historical groups on EVERY touched position. Validate every historical/proposed child/range and reserve combined group/entry/component limits before arithmetic. Reuse the SAME private CostingMath/flow core; do not introduce alternative transfer/FIFO/average calculations or weaken the original ungrouped100k-event limit.

Before comparing, rebuild the baseline from raw snapshot evidence using the existing reconciliation, checking all stored entries/layers/consumptions, final positions and original fingerprint. Never trust a supplied Blocks projection. Rebuilding derived blocks does not prove that caller-supplied evidence came from an authorized or complete database read; no API may accept a snapshot object as client authority. Only the authorized loader may provide production evidence. Source/version/policy revalidation remains necessary for future approval/execution.

Replay the proposed schedule from empty positions under the same common method/currency. Return immutable per-original-entry differences (including BOTH transfer legs and changed running balances), complete original/proposed final position totals, proposed child costs, and the full revised simulated layer trace. Include unchanged positions in final totals; include any changed trajectory even when the entry's own amount stays the same. Recompute costs on every downstream warehouse, not merely the root. Any shortage, invalid/cyclic/unsupported/incomplete evidence, collision, limit or cancellation refuses the entire comparison with no partial output.

Baseline and revised arithmetic each retain their existing400k component-work cap; comparison performs at most those two replays, under a shared caller cancellation/deadline for future application integration. Root/discovery/database budgets remain global for the single load, never reset per component. The proposed trace/fingerprint is simulation evidence, NOT journal adjustments, persisted layer IDs, a source approval, period legality, account/dimension selection or execution permission. No original journals/cost operations are modified. D044/D045, Final Closed periods, approval/SoD/audit/legal configurations and complete Web/Tauri delivery remain mandatory before whole-phase completion.

Required regression coverage: both methods; exact backdated receipt/issue/transfer changes across chained and returning transfers; multi-root disconnected histories joined by a proposal; empty destination; multiline child rounding; same-date ties across both endpoints; deterministic fingerprints/IDs; all original entry and final position mapping; preserved FIFO lineage and closed/free layers; shortage on a downstream warehouse; malformed/counterfeit baseline or proposal; unsupported histories; cancellation and combined limits. PostgreSQL comparisons must prove original rows/journals unchanged. Independent full-diff review and exact-head CI remain required; no public production caller is introduced by this internal checkpoint.

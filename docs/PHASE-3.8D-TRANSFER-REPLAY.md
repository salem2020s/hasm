# Internal ordinary transfer replay contract

Status: internal common-method arithmetic helper implemented and locally tested; authorized closure, real-layer mapping, snapshot/scheduler integration and the public feature remain unimplemented. D044/D045, the complete phase design and conversion contract remain binding. This contract does not enable backdated posting, conversion, public preview or execution.

## Boundary and reuse

Reuse CostReplay's private per-position state and existing CostingMath. One pure calculation covers one item's explicitly classified, already ordered ordinary receipt, issue and transfer groups across declared positions, starting empty. One common approved method and currency precision apply; cross-epoch/mixed-method conversion, reversals, stocktake and negative obligations remain unsupported. The future authorized snapshot adapter must prove completeness, provenance, classification and affected closure and use ReplaySchedule; this helper cannot prove omitted history exists. Never relabel unsupported history as ordinary events.

No database, clock, API, DI registration, production caller, journal, permission grant or mutable external cursor. Only a complete successful immutable result escapes; cancellation, inconsistent input, shortage or resource exhaustion discards the entire calculation.

## Input and state contracts

- Declare unique nonempty position IDs, bounded at10,000. Validate the complete batch of at most100,000 operation groups before arithmetic: unique nonempty group IDs, declared positions, supported kinds, exact positive quantities below the existing user quantity cap and permitted precision. Receipts alone supply a nonnegative amount below the existing receipt-input cap; issues/transfers cannot supply a cost. Transfers require two distinct declared positions. Ordinary receipts/issues cannot carry a destination.
- Each transfer computes source outflow through the same FIFO/average rule, then carries EXACTLY that quantity/value to the destination without a second rounding. Derived value may exceed a single receipt-input cap after several valid receipts; aggregate fixed-unit conversion bounds still apply. A transfer creates no company quantity or value.
- FIFO source consumptions become separate destination layers, in the same order, with each exact quantity/amount and source-layer lineage. Never collapse them into one averaged layer. Average positions carry only the exact aggregate value. This matches InventoryCostingService.TransferAsync; mixed-method/epoch behavior requires its separate reviewed conversion contract.
- Existing destination layers retain arrival precedence. Returning stock through another transfer creates new incoming layers; it does not merge into or reopen an original layer and is not a reversal.
- Retain immutable created-layer evidence: position, group, component sequence, layer identity, optional source-layer identity, original quantity and amount. Receipts use their unique group ID as synthetic layer identity. A transferred component uses a versioned deterministic identity derived from its group ID and source-layer identity, independent of culture, traversal order and mutable amounts. Proposed encoding: SHA256 of UTF8 `hasm-replay-mirror-v1` plus a NUL byte, lowercase32-digit group GUID, colon, lowercase32-digit parent-layer GUID; first16 hash bytes interpreted as a big-endian GUID. These are simulation identities, never replacements for persisted database layer IDs. The future adapter must bind real provenance explicitly.
- Detect identity collisions instead of silently merging components. Reserve all input group IDs before generating mirror identities, and keep every generated identity unique across the calculation.
- A shared budget permits at most400,000 FIFO component-work units: one for each created receipt or mirrored layer (including its retained immutable creation/provenance evidence), plus one for every layer-consumption edge (including its planned take and retained consumption evidence). Free/zero-value components count identically. Reserve before allocating the corresponding state/planning/output row and check cancellation in these loops. This is not400,000 per position or per transfer. Event/position limits separately bound average-mode steps and output; repeated large-layer transfers cannot allocate unbounded evidence.
